# 全領域差分の設計 (design-fullarea-diff.md)

`scripts/diff.sh` (step03) が作る差分 docx の仕組みと、その設計の理由をまとめる。差分の出し方 (コマンド) は
[`docs/usage-guide.md`](usage-guide.md) §3、パイプライン全体の中での位置づけは [`docs/architecture.md`](architecture.md) §2.3 にある。

> 本書はエンジニア以外も読む前提で書く。略語は初出で補足する。ファイルパス・コマンド名・関数名・要素名
> (`w:ins`、`panflute` など) は英語のまま書く。

---

## 0. 要約

- 差分は **構造保持型の AST 差分** で作る。旧版・新版の原稿をそれぞれ pandoc の AST (Abstract Syntax Tree、抽象構文木) に
  読み、**構造を一切壊さずに、変わった語句だけを目印で包む**。追加は青、削除は赤の取り消し線で docx に出る。
- 発想は latexdiff と同じである。latexdiff が全領域の差分を出せるのは「整形済みのソースに目印 (`\DIFadd` / `\DIFdel`) を
  差し込むだけで、`\title`・`\caption`・`tabular` などの構造を温存する」からで、本テンプレートはそれを LaTeX ではなく
  **pandoc の AST の上で**行う。
- pandoc は `custom-style` Div・`.textbox` Div・生 OOXML (Office Open XML) ブロック・表を無損失で往復できる (§1.1)。
  したがって AST を直接突き合わせれば、**タイトル・著者・所属・抄録・キーワード・本文・表・テキストボックスの中の表**の
  すべてを差分にできる。
- **pandiff は使わない** (§1.2・§1.3)。pandiff は文書を HTML のテキストに直して語単位の差分を取る道具で、出力のときに表を
  HTML に潰し、`custom-style` Div・`.textbox` Div・生 OOXML を捨てる。これは設計上の挙動で、オプションでは直せない。
- docx への描画は **pandoc の標準の仕組み**で足り、生 OOXML を手で書かない (§4)。直接 OOXML を触るのは、生成した docx の
  `word/styles.xml` に文字スタイルを 2 つ (`DiffAdd` / `DiffDel`) 入れる後処理だけである。

---

## 1. 根拠 (pandoc 3.6.4 / pandiff 0.8.0 で確かめたこと)

### 1.1 pandoc 単体は全構造を温存する

`pandoc new.md -f markdown -t markdown` で往復させると、`custom-style` Div・`.textbox` Div (width / page 属性つき)・
生 `{=openxml}` ブロック・表のすべてが無傷で戻る。**構造が失われるのは pandoc のせいではない。**

### 1.2 pandiff は「検出はできるが、出力で構造を捨てる」

`pandiff old.md new.md` は、タイトル・図のキャプション・表のセル・**テキストボックスの中のセル**まで差分を正しく検出する。
ところが出力では `custom-style` Div の包みが消え、表が HTML になり、生 openxml が落ちる。

### 1.3 pandiff は AST の差分ではなく、テキストの語の差分である

`pandiff old.md new.md -t native` (pandiff の内部の AST) を見ると、差分の記法 (CriticMarkup) が**文字列そのもの**
(`Str "information{++"`、`Str "validation++}"`) として埋まり、表は `RawBlock (Format "html")` になっている。pandiff は内部で
各文書を HTML にして `node-htmldiff` で語単位の差分を取り、出力のときに `fenced_divs`・`pipe_tables`・`grid_tables`・
`raw_attribute` を**無効にした Markdown** に書き戻す。構造が壊れるのは pandiff の設計の根幹で、設定では避けられない。

### 1.4 Span から docx への描画は pandoc の標準で成り立つ

| 入力 (Markdown のインライン) | docx の出力 | 用途 |
|---|---|---|
| `[changed]{custom-style="DiffAdd"}` | `<w:rStyle w:val="DiffAdd"/>` (文字スタイルの参照) | **色ハイライト** (本テンプレートの経路) |
| `[added]{.insertion}` | `<w:ins>` (Word の変更履歴: 挿入) | Word の変更履歴 (§4 の代わりの経路) |
| `[removed]{.deletion}` | `<w:del>` + `<w:delText>` (Word の変更履歴: 削除) | 同上 |

どれも**生 OOXML を手で書かず**、Span にクラスか属性を付けるだけで pandoc の docx ライタが正しい要素を出す。

pandoc の**生インライン OOXML** (`` `...`{=openxml} ``) でも色付きの run (`<w:r><w:rPr><w:color>`) は書けるが、文脈によっては
docx を壊す既知の問題がある (jgm/pandoc #5094 / #6933)。本テンプレートは、より安定して使い回しやすい文字スタイルの方式を採る。

## 2. アーキテクチャ

### 2.1 採らなかった経路 — pandiff でテキストに落としてから色を付ける

```
old.md, new.md
  → pandiff (HTML の語差分 → CriticMarkup のテキスト)   ← 構造が壊れる (Div / 表 / openxml が失われる)
  → 壊れた CriticMarkup をスクリプトで補修する           ← 脆く、壊れ方が変わるたびに直しが要る
  → 角括弧の span → 生 OOXML の run で色付け             ← 平らなテキストに潰れた引用・相互参照が壊れる
  → docx
```

手軽だが、構造が壊れる段 (pandiff) を最初に通るので、後段でどれだけ補っても「タイトル・著者・テキストボックスは差分の対象外
(新版で差し替える)」になる。補修の段も、pandiff の出力の壊れ方に依存して脆い。

### 2.2 採った経路 — 構造保持型の AST 差分

```
old.md ──► pandoc -t json ─┐
new.md ──► pandoc -t json ─┤
                           ▼
        構造保持 AST 差分 (Python + panflute。二層のアルゴリズム §3)
          ・構造 (custom-style Div / 表 / .textbox Div / 生 openxml / 図) は壊さずに温存する
          ・変わった語句だけを Span (.diff-add / .diff-del) で包む
                           │
                           ▼  マージした AST (構造を温存 + 差分の span)
        pandoc -f json (pandoc-crossref → generic-style.lua → citeproc → color-diff.lua → docx)
          ・差分の span は §4 のとおり文字スタイル DiffAdd / DiffDel に写す
                           │
                           ▼
        OOXML の後処理 (build と共用。表の罫線・ネイティブ SVG の埋め込み・テキストボックス化)
          ・色は run のプロパティとして乗っているので、テキストボックスの中にもそのまま運ばれる
          ・word/styles.xml に DiffAdd / DiffDel を入れる (§4.2)
                           │
                           ▼  data/step03_diff/main_diff.docx
```

要点は「**pandiff を通さない**」「**構造を一度もテキストや HTML に潰さない**」の 2 つである。これで §2.1 の 3 つの弱点
(構造の喪失・補修の段・平らなテキストへの潰れ) が原因ごと無くなる。

## 3. 差分アルゴリズム (二層)

pandoc の AST を木として差分する既製の道具は無いので、自前で持つ (`main/step03_diff/ast_diff.py`)。構成は latexdiff や
木の差分の定石と同じ**二層**で、その間に「変更されたブロックの対応付け」(レベル1.5) を挟む。

### レベル1：ブロック列の整列 (構造の対応付け)

- 2 つの文書の `Blocks` (段落・見出し・表・Div などの並び) を、`difflib.SequenceMatcher` (LCS = 最長共通部分列の系統) で
  整列する。
- 等しいかどうかは「ブロックの種別 + 正規化したテキスト」で判定する。種別には、Div なら `custom-style` とクラス、見出しなら
  レベルを含める (Title の Div と Author の Div、レベルの違う見出しを取り違えないため)。
- 結果は「一致したブロック」「追加されたブロック」「削除されたブロック」「入れ替わった区間 (`replace`)」に分かれる。
  一致したブロックは新版のものをそのまま使う。
- **入れ物の要素 (`Div`・`Table`・箇条書き・`BlockQuote`・図) には再帰する**。Div → その中の Blocks、Table → 行 → セル →
  Blocks、と型のついた木をたどる (pandiff との決定的な違い。HTML に潰さない)。

### レベル1.5：変更 (replace) ブロックの対応付け

- レベル1 の整列は「完全に一致したブロック」を目印にするだけである。**1 語でも変わった段落は一致しない**ので、そのままでは
  「削除」と「追加」に分かれ、段落まるごとの赤と青の二重表示になって、語単位の差分 (レベル2) に回らない。そこで
  レベル1とレベル2の間に**変更されたブロックの対応付け**を置く。
- 手順: レベル1 の `replace` 区間の中で、旧ブロックと新ブロックを**同じ種別どうし**で総当たりし、**類似度** (語の並びの
  `difflib` の比。0〜1) が**しきい値 0.5 以上**の組を候補にする。類似度の高い順に 1 対 1 で割り当て、最後に順序が交差する組を
  外す (旧の位置が新の順に単調に増える組だけを残す)。残った組を「同じブロックの改稿」とみなしてレベル2 の語差分へ送り、
  組にならなかったものは「全削除」「全追加」として着色する。削除したブロックは新版の流れの中の元の位置に差し込む。
- 類似度に使う語は `Str` を語に割って集める。セルを区切りなしで連結した文字列で比べると、単語や数値のセルばかりの表で
  類似度が常に 0 になり、変更した表が組にならずに表全体が「旧 = 全部赤 / 新 = 全部青」に二重化するため。
- 種別が違う変更 (`Para` ↔ `Header` など) は対応付けない。
- **この工程が無いとレベル2 は完全に一致したブロックにしか当たらず (差が無いので) 何もしない**。二層の差分の品質を決める
  中核はここにある。しきい値は `ast_diff.py` の `SIMILARITY_THRESHOLD` (§7 の「大きな改稿」の境界はこの値で決まる)。

### レベル2：対応したブロックの中の語差分

- 同じ種別で対応した葉のブロック (`Para` / `Plain` / `Header` / キャプション / セルの中の段落) について、`Inlines` (文字・強調・
  引用などの並び) をトークンの列に展開し、`difflib.SequenceMatcher` で語単位の差分を取る。pandoc は地の文を `Str` (語) と
  `Space` にすでに分けているので、要素ごとのトークン化がそのまま語単位の差分になる。
- 変わった語を `Span` (クラス `diff-add` / `diff-del`) で包んで組み立て直す。置き換えは latexdiff と同じく「削除 (旧) →
  追加 (新)」の順に並べる。包みの両端の空白は Span の外に出す (色付きの run が空白で広がらないように)。
- **`Emph` / `Strong` / `Cite` / `Link` / `Math` / `Image` / `Code` などは 1 つの不透明なトークン**として扱い、要素のまま
  温存する。変わっていない引用・相互参照は生きたまま残り、citeproc と pandoc-crossref がマージした AST の上で解決する。

### 表の扱い

- 見出し行 (`TableHead`)・本体 (`TableBody`)・脚 (`TableFoot`) ごとに、行を整列する (等しいかどうかは行のセルのテキストを
  正規化して連結したもの)。対応した行はセルを**位置で**突き合わせ、セルの中のブロックに再帰する。追加された行は全部青、
  削除された行は全部赤で、新しい表の中に残す。
- 表の骨格 (列の指定・識別子) は新版のものを使う。セル結合 (colspan / rowspan) のある表は位置の突き合わせが曖昧になりうる
  (§7)。医学論文の多くの単純な表は結合が無く、位置の一致で足りる。

### キャプション・図・生 openxml

- 図と表のキャプションは葉のブロックとして語差分の対象にする (latexdiff が `\caption` を差分にするのと同じ)。
- 図そのもの (画像の要素) は新版のものを温存する。生 openxml のブロックは、変わっていなければ温存する (変わったときは §7)。

## 4. 描画 (docx への注入をどう実現するか)

### 4.1 原則：pandoc の標準の仕組みを使い、生 OOXML の run を手で書かない

§1.4 のとおり、生インライン OOXML は文脈によって docx を壊す。代わりに pandoc が公式に対応する仕組み (文字スタイル) を使う。

### 4.2 本テンプレートの経路：色ハイライト (文字スタイル)

- 差分の span を **文字スタイル** `DiffAdd` (青 `#2E74B5`) / `DiffDel` (赤 `#C00000` + 取り消し線) に写す。写すのは Lua
  フィルタ `main/00_setup/filters/color-diff.lua` で、`.diff-add` / `.diff-del` のクラスを `custom-style="DiffAdd"` /
  `"DiffDel"` に付け替えるだけである。フィルタの順は crossref → generic-style → citeproc → **color-diff (最後)**
  (引用を解決したあとに写す)。
- `custom-style="DiffAdd"` は pandoc の docx ライタが `<w:rStyle w:val="DiffAdd"/>` を出すだけで、**色そのものは持たない**。
  色の実体は、差分の後処理 (lxml) が**生成した docx の `word/styles.xml` に毎回入れる** (同じ ID のスタイルを一度消してから
  入れ直すので、何度入れても同じ結果になる)。差分版は雑誌の書式を保つため build と同じ reference.docx を使うので、雑誌が
  配るテンプレート (この 2 スタイルを持たない) でも差分の色が出る。**定義を入れ忘れると、黙って無着色になる**ので、この
  注入は省けない。定義は reference.docx を作るときに使う `patch_reference_docx.inject_diff_styles` と同じもの (1 か所で持つ)。
- 色は run のプロパティ (`w:rStyle`) として乗るので、後処理が run をテキストボックスへ写すときにもそのまま運ばれる。
  **テキストボックスの中の表のセルも、これで色つきの差分になる**。
- 変わった箇所の中の引用・相互参照が壊れないのは、生 OOXML を避けたからではなく、**pandiff を通さず `Cite`・相互参照を
  要素のまま温存する**からである (色を生の run と文字スタイルのどちらで付けるかとは独立)。文字スタイルの方式は、それに
  加えて描画を安定させる。

### 4.3 代わりの経路 (実装していない)：Word の変更履歴

- 同じ AST の差分から `insertion` / `deletion` のクラスを出せば、pandoc が `<w:ins>` / `<w:del>` を出し、査読者が Word の上で
  承諾・却下できる本物の変更履歴になる (§1.4)。
- ただしテキストボックスの中の `w:ins` の表示は閲覧する環境によって変わるので、本テンプレートは色の経路だけを実装している。
  2 つの経路は同じ差分エンジンから出し分けられる設計で、足すなら `color-diff.lua` の写し先を変えることになる。

## 5. 全領域の対応 (どの領域がどの層で解決するか)

| 領域 | 解決する層 | 仕組み | 生 OOXML の直接操作 |
|------|-----------|--------|-------------------|
| タイトル / 著者 / 所属 (`custom-style` Div) | AST + 描画 | Div を温存しつつ中を語差分 → `DiffAdd` / `DiffDel` の文字スタイル (Title などの段落スタイルと併存する) | 不要 |
| 抄録 / キーワード | AST + 描画 | 葉のブロックの語差分 | 不要 |
| 本文 | AST + 描画 | 同上 | 不要 |
| 図表のキャプション | AST + 描画 | キャプションを葉のブロックとして語差分 | 不要 |
| 表のセル | AST + 描画 | 行の整列 → セルの位置の突き合わせ → セルの中の語差分。表は表のまま色がつく | 不要 |
| テキストボックスの中の表のセル | AST + 描画 + 後処理 | `.textbox` Div を温存して中を語差分 → 色つきの run を後処理がテキストボックスに写す | 不要 |
| 図・引用 `Cite`・相互参照・数式 | AST | 要素のまま温存する (変わったときだけ要素ごと削除 + 追加) | 不要 |
| 生 openxml のブロック | AST | 温存する | 不要 |
| `DiffAdd` / `DiffDel` の色の定義 | 後処理 | 生成した docx の `word/styles.xml` に入れる (§4.2) | **必要 (スタイルの定義だけ)** |

**結論**: インラインとセルのテキストの差分はすべて AST の層と文字スタイルで解決し、本文の OOXML を直接いじる必要は無い。
直接触るのはスタイルの定義を入れる 1 か所だけである。ブロックまるごとの追加・削除に行単位の網掛けを付けるような見た目の
強化は、OOXML の直接操作が要るので実装していない。

## 6. 実装方針

### 6.1 言語と依存

- **Python + panflute** (`docx-paper-template-pandoc` コンテナに版を固定して入れてある)。2 つの文書を `pandoc -t json` で読み
  (`panflute.load`)、Python で二層の差分を取り、マージした 1 つの `Doc` を `panflute.dump` して `pandoc -f json -t docx` に渡す。
  `difflib` は標準ライブラリ。
  - pandoc のフィルタ (`--filter`) は 1 つの文書しか受け取れないので、2 つの文書を同時に扱うこの処理には使えない。
  - Lua フィルタは LCS を標準で持たず、2 つ目の文書の受け渡しも煩雑で向かない。

### 6.2 モジュールの分担

| ファイル | 役割 |
|------|------|
| `scripts/diff.sh` | 入口。revision の形 (`HEAD~1` など。旧版を git から取り出す) と 2 ファイルの形を受け、図の前処理 (step01) を回してからコンテナで `diff_docx.py` を呼ぶ |
| `main/step03_diff/diff_docx.py` | 2 つの版を AST にし、`ast_diff` でマージし、build と同じ引数 (reference.docx / CSL / 文献 / defaults.yaml / フィルタ) で docx にし、build と共用の後処理を掛け、`DiffAdd` / `DiffDel` を入れる |
| `main/step03_diff/ast_diff.py` | 二層の差分エンジン。入出力を持たない (Doc → Doc)。テストしやすさのため |
| `main/00_setup/filters/color-diff.lua` | `.diff-add` / `.diff-del` → `custom-style` の付け替え (§4.2) |
| `main/step02_build/postprocess.py` | build と共用の後処理 (表の罫線・ネイティブ SVG の埋め込み・テキストボックス化) |
| `main/00_setup/lib/patch_reference_docx.py` | `inject_diff_styles` (`DiffAdd` / `DiffDel` の定義。reference.docx の生成と差分の後処理が共用) |

図は新版の図ツリー (`data/step01_figures/`)、文献は新版の `ref.bib` で解決する。雑誌プロファイルから読むのは
`reference_doc` と `csl` の 2 つだけで、記事種別は出力を変えない (`--article-type` は build と引数を揃えるため、また知らない
種別を早く止めるために受ける)。

### 6.3 実装上の約束

- **メタデータの引き継ぎ**: マージした `Doc` は**新版の `Meta`** (crossref の接頭辞 figPrefix / tblPrefix・citeproc の設定・
  `lang` など) を使う。読むときも描くときも build と同じ `defaults.yaml` を渡し、図表番号と引用の挙動を build と揃える。
- **`difflib` の autojunk は切る**: `SequenceMatcher(autojunk=False)`。語数の多い段落で、よく出る語を「ゴミ」として
  飛ばすせいで直感に反する差分になるのを避ける。
- **不透明なトークン**: `Cite`・数式・`Link`・`Emph` / `Strong` などは 1 つのトークンとして語差分に載せる。**要素の内部だけの
  変更は、要素まるごとの置き換えになる** (語の中の差分は効かない)。コードブロック・生 openxml・水平線などのブロックも同じく
  不透明で、変わっていなければ温存し、変わっていれば旧と新を並べる (色は付けられない。§7)。
- **削除した図**: 削除した図の画像は作業ツリーに無いことがあり (図の前処理は新版が基準)、画像を残すと pandoc が図を落として
  後処理の図の数の照合が差分の生成を止める。そこで削除した図は画像を描かず、**キャプション (赤の取り消し線) だけ**を
  `.deleted-figure` Div に畳んで残す。削除した図は図番号を使わないので、新版の図番号がずれない利点もある。追加した図は
  画像があるので温存する。

### 6.4 確かめ方 (動作例で)

`data/dummy/` の原稿で次を確かめる (`bash scripts/diff.sh <旧> <新>` で作り、Word か LibreOffice で開いて見る)。

1. 本文の語差分 (青 / 赤 + 取り消し線)
2. タイトル・抄録 (`custom-style` Div) の差分
3. 表のセルの差分
4. テキストボックスの中の表のセルの差分
5. 引用 `Cite`・相互参照・図が差分版でも壊れていないこと

## 7. 既知の制限

latexdiff でも弱く、本テンプレートでも制限として残るもの:

- **段落・文の「移動」**: 削除 + 追加として出る (移動は検出しない)。
- **セル結合の複雑な表**: colspan / rowspan が絡む表の整列は曖昧になりうる。
- **大きな改稿の境界**: 段落の大きな改稿を「変更」と見るか「全削除 + 全追加」と見るかの境界は経験則になる (レベル1.5 の
  しきい値 0.5)。
- **引用番号の振り直し**: 削除した引用 (`DiffDel` の表示) も AST の上では生きた `Cite` のまま温存されるので、citeproc はそれにも
  番号を振り、文献リストにも載せる。番号順の引用様式 (Vancouver 系) では、差分版の引用番号が旧版とも新版とも一致しないことがある。
- **文献リストそのものは差分にならない**: citeproc がマージした AST から作り直すので、追加・削除した文献に色は付かない。
- **相互参照の番号**: 図表を追加・削除すると、差分版の図番号・表番号が旧版とも新版とも一致しないことがある。
- **数式の中の差分は無い**: 数式は要素のまま温存するので、変わった数式は式まるごとの削除 + 追加として出る (本文の語差分とは
  粒度が違う)。
- **ラベルつきの数式を編集すると、その式への相互参照が壊れる**: `$$ ... $$ {#eq:x}` の中身を変えると、式が差分の span
  (`DiffDel` / `DiffAdd`) で包まれてラベル `{#eq:x}` が式から離れるので、pandoc-crossref が式を認識できず、その式への参照
  `[@eq:x]` が `¿eq:x?` (未解決の印) になる。数式を変えた版どうしの差分でだけ起きる。
- **コードブロック・生 openxml・水平線の変更は色が付かない**: run のスタイルを載せられないので、変えると着色されずに
  **旧と新の 2 つが並ぶ** (どちらが旧か新かは見た目では分からない)。とくに生 openxml のブロック (` ```{=openxml} `) が
  段組み・節区切りなどの構造の指示だと、二重に効いて体裁が崩れうる。
- **見出しのレベルだけの変更**: `# X` → `## X` のようにレベルだけ変えて語句が同じでも、種別が違う (`Header:1` ↔ `Header:2`)
  ので対応付けされず、同じ見出しの**全削除 + 全追加** (赤の取り消し線 + 青) になる。
- **表の列の追加・削除**: セルを位置で突き合わせるので、列を途中に足したり消したりすると後ろの列がずれ、変わっていない
  セルまで赤と青になりうる (表は二重にならず 1 つに保たれる)。
- **削除した図は画像を描かない**: キャプション (赤の取り消し線) だけが残る (§6.3)。
- **語の間に空白の無い言語の本文**: pandoc は空白で語を区切るので、日本語のように空白の無い文は句点などで区切られた
  まとまりが 1 つの語になり、1 文字の変更でもまとまりごとの削除 + 追加になりうる。

## 付録：確かめるためのコマンド

pandoc は本テンプレートの pandoc コンテナで動く (pandiff はコンテナに入れていないので、§1.2・§1.3 を見るには別に用意する)。

```bash
# pandoc は構造を温存する (出力に custom-style Div・.textbox Div がそのまま残る。{=openxml} ブロックや表も同じ)
docker compose -f docker/docker-compose.yml run --rm -u "$(id -u):$(id -g)" pandoc \
  pandoc data/dummy/main.md -f markdown -t markdown

# pandiff は構造を壊す (検出はできている。pandiff を別に入れた環境で)
pandiff old.md new.md -t markdown
pandiff old.md new.md -t native     # 内部の AST に CriticMarkup が文字列のまま出る

# Span → docx の描画経路
#   [x]{custom-style="DiffAdd"}      -> <w:rStyle w:val="DiffAdd"/>
#   [x]{.insertion} / {.deletion}    -> <w:ins> / <w:del> + <w:delText>
```
